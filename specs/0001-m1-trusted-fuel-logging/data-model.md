# 0001 — Data model

- **Status:** draft, awaiting review
- **Scope:** the canonical domain model for M1
- **Source of truth once built:** the Drizzle schema in
  `packages/api/src/db/schema`. This document is the design that schema realizes.

The model is designed fresh. It does not inherit the legacy prototype schema.
Legacy review and migration are spec `0002`.

## Representation decisions

### D-1 Canonical units

The database stores one representation. Input and display convert at the API
edge.

| Quantity | Canonical unit | Column type |
|---|---|---|
| Distance, odometer | metre (integer) | `bigint` / `integer` |
| Volume | millilitre (integer) | `bigint` / `integer` |
| Money | minor currency unit, for example cent (integer) | `bigint` |
| Date of a fill-up | calendar date, no time | `date` |
| Timestamps | UTC instant | `timestamptz` / `text` ISO-8601 |

Reason: integers remove floating-point error from reconciliation and metrics.
Metre and millilitre give more than enough precision for odometer and pump
readings. The profile's unit system and currency drive conversion only.

*Open:* confirm integer millilitre is precise enough for pump volume, or move to
a fixed 3-decimal litre stored as integer thousandths. See `open-questions.md`.

### D-2 Currency

One currency per profile, stored on the profile as an ISO-4217 code. Each fuel
entry also records the currency code in force when it was created, so a later
profile currency change does not corrupt history. Cross-currency conversion is
out of scope.

### D-3 Source unit audit

Each fuel entry records the unit system used to create it (`metric` or
`imperial`) and the raw submitted values, for audit and for a faithful export.
The canonical integer columns are authoritative.

### D-4 Identifiers

UUID v7 primary keys, stored as `uuid` on PostgreSQL and `text` on SQLite,
generated by the application. UUID v7 keeps keys time-ordered for stable
pagination.

## Entities

### profile

One row. The account holder.

| Field | Type | Null | Notes |
|---|---|---|---|
| `id` | uuid | no | primary key |
| `display_name` | text | no | 1..100 chars |
| `unit_system` | text | no | `metric` or `imperial` |
| `currency_code` | text | no | ISO-4217, 3 letters |
| `time_zone` | text | no | IANA name, for the future-date check |
| `created_at` | timestamptz | no | |
| `updated_at` | timestamptz | no | |

Constraints: `unit_system in ('metric','imperial')`. `currency_code` matches
`^[A-Z]{3}$`. A partial unique index or a single-row guard enforces exactly one
profile.

### api_token

Bearer tokens for API access.

| Field | Type | Null | Notes |
|---|---|---|---|
| `id` | uuid | no | primary key |
| `token_hash` | text | no | SHA-256 of the token, unique |
| `label` | text | yes | for example `bootstrap`, `cli` |
| `created_at` | timestamptz | no | |
| `revoked_at` | timestamptz | yes | null means active |

The plaintext token is shown once at creation and never stored.

### vehicle

| Field | Type | Null | Notes |
|---|---|---|---|
| `id` | uuid | no | primary key |
| `profile_id` | uuid | no | foreign key to `profile.id`, on delete restrict |
| `name` | text | no | 1..100 chars, unique per profile among non-archived |
| `make` | text | yes | |
| `model` | text | yes | |
| `year` | integer | yes | 1900..2100 |
| `fuel_type` | text | yes | `gasoline`, `diesel`, `ev`, `hybrid`, `other` |
| `initial_odometer_m` | bigint | no | canonical metres, 0 or greater |
| `archived_at` | timestamptz | yes | null means active |
| `created_at` | timestamptz | no | |
| `updated_at` | timestamptz | no | |

Constraints: `initial_odometer_m >= 0`. `year` range check. `fuel_type` in the
allowed set when present. Foreign key to profile with `on delete restrict`.
Index on `(profile_id, archived_at)`.

### fuel_entry

| Field | Type | Null | Notes |
|---|---|---|---|
| `id` | uuid | no | primary key |
| `vehicle_id` | uuid | no | foreign key to `vehicle.id`, on delete restrict |
| `entry_date` | date | no | calendar date of the fill-up |
| `odometer_m` | bigint | no | canonical metres, 0 or greater |
| `volume_ml` | bigint | no | canonical millilitres, greater than 0 |
| `total_cost_minor` | bigint | no | canonical minor units, 0 or greater |
| `currency_code` | text | no | ISO-4217 in force at creation |
| `is_full_tank` | boolean | no | default true |
| `notes` | text | yes | 0..1000 chars |
| `source_unit_system` | text | no | `metric` or `imperial` at creation |
| `source_payload` | jsonb / text | no | raw submitted values, for audit and export |
| `created_at` | timestamptz | no | |
| `updated_at` | timestamptz | no | |

Constraints: `volume_ml > 0`. `total_cost_minor >= 0`. `odometer_m >= 0`.
`currency_code` matches `^[A-Z]{3}$`. `source_unit_system` in the allowed set.
Foreign key to vehicle with `on delete restrict`. Index on
`(vehicle_id, entry_date desc, created_at desc)` for history and pagination.

### schema_meta

One row. Bootstrap and version state.

| Field | Type | Null | Notes |
|---|---|---|---|
| `schema_version` | integer | no | current applied version |
| `applied_at` | timestamptz | no | |
| `chotu_build` | text | no | build that applied it |

Drizzle's own migration journal table sits alongside this. `schema_meta` is the
value FR-1.3 validates.

## Cross-entity invariants

- **INV-1 Ownership chain.** `fuel_entry` to `vehicle` to `profile`. Enforced by
  foreign keys and re-checked in the API. No entry without a vehicle. No vehicle
  without the profile.
- **INV-2 Odometer progression.** Order a vehicle's entries by `entry_date`,
  then `created_at`. Each entry's `odometer_m` is greater than or equal to the
  previous entry's, and greater than or equal to the vehicle's
  `initial_odometer_m`. A strict decrease is rejected at write time
  (`odometer_decrease`). A tie passes the write and is reported by
  reconciliation. *(Confirm the tie rule.)*
- **INV-3 Archived vehicle is read-only for entries.** No create or update of a
  `fuel_entry` whose vehicle has a non-null `archived_at`.
- **INV-4 Future date bound.** `entry_date` is at most one day after the current
  date in `profile.time_zone`. *(Confirm the window.)*
- **INV-5 Full-tank economy interval.** Fuel economy over an interval is defined
  only between two `is_full_tank` entries. First fill-up and partial fills
  produce no economy figure, not a misleading one. Metrics are phase 3. This
  invariant is recorded here so the schema keeps `is_full_tank`.

INV-2 and INV-4 are checked in the application because they need ordering and the
profile time zone. The database still enforces the per-row checks (non-negative,
positive volume, valid enums, foreign keys).

## Derived values, not stored

Computed on read. Listed so nobody adds a column for them.

- Price per litre or per gallon: `total_cost_minor / volume_ml`, converted.
- Distance since the previous entry: difference of `odometer_m`.
- Fuel economy over a full-tank interval: sum of volume over distance.

## Adapter notes

| Concern | PostgreSQL | SQLite |
|---|---|---|
| UUID | `uuid` | `text` |
| Big integer | `bigint` | `integer` (64-bit) |
| Boolean | `boolean` | `integer` 0 or 1, mapped by Drizzle |
| Timestamp | `timestamptz` | `text` ISO-8601 UTC |
| JSON | `jsonb` | `text` with JSON validation in the app |
| Date | `date` | `text` `YYYY-MM-DD` |

Drizzle exposes both dialects. The persistence layer picks the column helpers by
adapter. Application and route code see one set of domain types.

## Minimum database privileges

Documented for FR-1.5. Values to finalize during the plan.

- **Bootstrap role.** Create schema, create table, create index, alter table,
  insert into `schema_meta` and the migration journal. Scoped to the Chotu
  schema only.
- **API role.** Select, insert, update, delete on the Chotu tables. No DDL. No
  access to other schemas.

## Fixtures

For FR-10 and AC-3, AC-6. Committed under `packages/api/test/fixtures`.

- `clean` — a valid profile, two vehicles, twenty ordered fuel entries.
- `duplicate` — two entries with the same vehicle, date, odometer, volume, cost.
- `orphaned` — an entry whose vehicle id is absent. Only loadable by bypassing
  the foreign key, to test the reconciliation report path.
- `odometer-decrease` — an entry that violates INV-2.
- `invalid-values` — zero volume, negative cost, bad currency code.
